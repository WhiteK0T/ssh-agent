# Аналоги: управление SSH-агентом и выбор ключей

Заметка о похожих инструментах и применимых к нашему проекту идеях.
Проверено **3 ноября 2026 года** по документации авторов. Аналоги не устанавливались
и не проверялись запуском; выводы ниже относятся к описанным возможностям.

## Что уже умеет наш скрипт

`ssh-agent.sh` — ручное управление ключами в Bash: меню со стрелками, SHA256-отпечатки,
индикатор загрузки, отметки нескольких ключей, добавление и выгрузка. Изменения
применяются сразу, история консоли и итоговый список сохраняются после выхода.

Запуск через `source` оставляет окружение агента в текущем терминале. Доступный
агент используется повторно, новый запускается при первом добавлении ключа.
Есть установка и удаление через `install.sh`. Подробнее — в [README](README.md).

## Краткое сравнение

| Инструмент | Основной сценарий | Отличие от нашего проекта |
| --- | --- | --- |
| [sshush](https://s-johri.github.io/sshush/) | Терминальное меню ключей, хостов и SSH-конфига | Ближайший аналог интерфейса; больше функций, отдельное приложение на Go |
| [keychain](https://github.com/danielrobbins/keychain) | Общий агент для нескольких терминалов и фоновых задач | Сохраняет данные подключения; ключи задаются командой, без меню выбора |
| [ssh-ident](https://github.com/ccontavalli/ssh-ident) | Разные наборы ключей для проектов и подключений | Выбирает идентичность автоматически по правилам |
| [ssh-find-agent](https://github.com/wwalker/ssh-find-agent) | Найти и выбрать уже работающий агент | Выбирает агент, а не файлы ключей |
| [Плагин Oh My Zsh](https://github.com/ohmyzsh/ohmyzsh/tree/master/plugins/ssh-agent) | Настроить запуск агента и загрузку ключей в Zsh | Загрузка по настройкам оболочки, без меню |
| [OpenSSH: AddKeysToAgent](https://man.openbsd.org/ssh_config#AddKeysToAgent) | Добавить ключ при SSH-подключении | Встроенная автоматизация; меню нет, агент должен работать |

## sshush: ближайший аналог меню

Показывает алгоритмы, отпечатки и состояние загрузки ключей. Enter или Space
переключает загрузку текущего ключа. Есть поиск, ключи по умолчанию, работа
с хостами и редактирование SSH-конфига. Для операций с агентом документация
требует работающий агент и заданный `SSH_AUTH_SOCK`.
[Возможности и управление](https://s-johri.github.io/sshush/).

В нашем меню Space отмечает ключи для групповой операции, Enter переключает
текущий ключ, а `a` / `d` применяются к отмеченным. Отпечатки и индикатор загрузки
уже реализованы; предлагать их как будущие улучшения больше не нужно.

## keychain: один агент между терминалами

Находит или запускает агент, загружает указанные ключи и сохраняет данные
подключения в `~/.keychain/`. Новые оболочки могут подключаться к тому же агенту.
Текущий upstream описывает Keychain 3 на Python; пакет дистрибутива может отличаться.
[Официальный README и настройка Bash](https://github.com/danielrobbins/keychain#60-second-quick-start).

Пример для ручного запуска в интерактивном Bash по синтаксису Keychain 3:

```bash
eval "$(keychain add --eval ~/.ssh/id_ed25519 ~/.ssh/id_work)"
keychain list
```

Для автозапуска нужен полный рецепт автора с отдельной обработкой
неинтерактивной оболочки. Наш скрипт сохраняет окружение в вызывающем Bash,
но не организует подключение независимых терминалов к общему агенту.

## ssh-ident: автоматический выбор идентичности

Обёртка над `ssh`, которая запускает агенты и загружает наборы ключей по правилам
для аргументов подключения или рабочего каталога. Подходит для разделения
рабочих и личных идентичностей. Для Git, rsync и других программ требуется
настроить вызов обёртки соответствующим способом.
[Описание и правила выбора](https://github.com/ccontavalli/ssh-ident).

## ssh-find-agent: выбор существующего агента

После `source ssh-find-agent.sh` команда `ssh-find-agent -c` позволяет выбрать
агент вручную, `ssh-find-agent -a` — первый найденный. Полезно, когда агент
работает, но текущий терминал не знает его сокет.
[README](https://github.com/wwalker/ssh-find-agent#usage).

Наш скрипт проверяет только агент из текущего окружения; поиск других сокетов
и выбор между несколькими агентами не реализованы.

## Oh My Zsh и Oh My Bash

У **Oh My Zsh** есть плагин `ssh-agent`: список `identities`, отложенная загрузка
`lazy`, срок хранения `lifetime` и использование доступного агента через
`honor-existing`. Последняя настройка существенна при наличии агента рабочего
стола: согласно документации, по умолчанию плагин может запустить собственный.
[Настройки плагина](https://github.com/ohmyzsh/ohmyzsh/blob/master/plugins/ssh-agent/README.md).

У **Oh My Bash** в проверенном каталоге штатных плагинов отдельный `ssh-agent`
не найден. Поэтому переносить настройку `plugins=(... ssh-agent)` из Oh My Zsh
в Bash как готовый рецепт нельзя. Это результат проверки штатного списка,
а не утверждение об отсутствии сторонних дополнений.
[Каталог плагинов Oh My Bash](https://github.com/ohmybash/oh-my-bash/tree/master/plugins).

## OpenSSH: автозагрузка и повторные запросы

`AddKeysToAgent` работает при использовании ключа через `ssh`:

| Значение | Поведение |
| --- | --- |
| `yes` | Добавить прочитанный ключ в работающий агент |
| `confirm` | Добавить с требованием подтверждать каждое использование |
| `ask` | Спросить разрешение перед добавлением |
| `no` | Не добавлять автоматически |

Эта настройка не запускает агент. Выгрузка через меню удаляет ключ из памяти,
но не запрещает SSH снова читать файл из `IdentityFile`. Поэтому `no` отключает
автодобавление, но не все запросы пароля. Повторные подключения приложения могут
вызывать новые запросы. Удаление ключа из агента и запрет его использования —
разные действия.
[Справочник OpenSSH](https://man.openbsd.org/ssh_config#AddKeysToAgent).

## Идеи для обсуждения

Следующие возможности пока не реализованы:

- **Срок хранения ключа** — выбор времени при добавлении через `ssh-add -t`,
  как в настройках keychain и плагина Oh My Zsh.
  [Параметр OpenSSH](https://man.openbsd.org/ssh-add#t).
- **Поиск по списку** — фильтрация имени или комментария, как в sshush.
- **Информация об агенте** — показать используемый сокет и доступный PID,
  чтобы проще разбирать взаимодействие с агентом рабочего стола.
- **Общий агент между терминалами** — отдельный режим с явным выбором,
  если появится такая потребность; ориентиры — keychain и ssh-find-agent.

Приоритеты — оценка для этого проекта, а не результаты сравнительного теста.
Текущий сценарий: управлять загрузкой ключей, сохраняя окружение Bash и вывод
терминала. Создание ключей, редактор хостов и SSH-конфига в него не входят.
